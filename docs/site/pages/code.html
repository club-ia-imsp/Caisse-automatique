def normaliser_uid(uid):
    return re.sub(r"[^0-9A-Fa-f]", "", uid or "").upper()

def ajouter_uid(uid, source="rfid"):
    uid_normalise = normaliser_uid(uid)
    # verrou, délai anti-double lecture, requête SQLite
    cursor.execute("SELECT uid, nom, prix, categorie FROM produits WHERE UPPER(uid) = ?", (uid_normalise,))
    # si l’UID est déjà présent : retrait ; sinon : ajout
normaliser_uid supprime chaque caractère non hexadécimal avec re.sub, traite une valeur absente comme une chaîne vide et transforme le résultat en majuscules.
ajouter_uid note l’heure, consulte dernier_scan_par_uid sous verrou et renvoie immédiatement si le même badge revient avant 2 secondes.
cursor.execute(..., (uid_normalise,)) utilise un paramètre SQLite, ce qui évite de concaténer l’UID dans le SQL. Le dictionnaire item reprend ensuite les quatre champs utilisés par l’interface.
La recherche d’index avec next(..., None) localise le même UID. pop et cart_total -= le retirent, sinon append et += l’ajoutent. last_scan est mis à jour dans les deux cas.

Interface · HTML, CSS et JavaScript

const cartBadge = document.getElementById('cartBadge');
let cart = [];
let total = 0;

async function refreshCart() {
  const response = await fetch('/api/cart?t=' + Date.now(), { cache: 'no-store' });
  const data = await response.json();
  cart = data.items || [];
  total = data.total || 0;
  renderCart();
}
setInterval(refreshCart, 1000);
getElementById conserve une référence aux éléments HTML que le script doit modifier. Les const ne changent pas de référence ; let est utilisé pour l’état qui évolue.
fetch appelle l’API ; l’horodatage et no-store évitent une réponse mise en cache. await attend la réponse puis le JSON sans bloquer l’interface.
data.items || [] garantit un tableau même si l’API ne renvoie pas d’articles. renderCart affiche cet état ; setInterval répète le rafraîchissement chaque seconde.
Le HTML fournit les zones identifiées par id et les boutons ; le CSS organise les cartes, couleurs, états disabled, vues masquées et adaptation mobile. Chaque règle CSS applique la propriété indiquée à son sélecteur : aucune logique métier n’y est cachée.

Arduino · .ino

#include <SPI.h>
#include <MFRC522.h>
#define SS_PIN 5
#define RST_PIN 22
MFRC522 rfid(SS_PIN, RST_PIN);

void setup() { Serial.begin(115200); SPI.begin(); rfid.PCD_Init(); }
void loop() {
  if (!rfid.PICC_IsNewCardPresent()) return;
  if (!rfid.PICC_ReadCardSerial()) return;
  // conversion de chaque octet en UID hexadécimal puis Serial.println(uid)
}
#include importe les bibliothèques SPI et MFRC522. Les #define donnent un nom aux broches, puis le constructeur crée l’objet lecteur avec ces deux broches.
setup s’exécute une seule fois : liaison série, bus SPI et lecteur sont initialisés. loop tourne continuellement.
Les deux conditions renvoient immédiatement tant qu’aucun tag n’est présent ou lisible. La boucle for parcourt chaque octet de l’UID ; le zéro initial garantit deux chiffres hexadécimaux. toUpperCase harmonise le format et Serial.println le termine par une nouvelle ligne, attendue par Python.
