ARCHITECTURE

Du tag RFID à l’écran mobile.

L’application fonctionne localement : le PC héberge Flask et SQLite, puis diffuse l’interface au navigateur du téléphone via le réseau Wi‑Fi.

[Tag RFID] → [MFRC522 + ESP32] → USB / port COM
                                      │ UID texte
                                      ▼
                         [backend.py : Flask]
                           │         │
                         SQLite    API HTTP
                           │         │
                           ▼         ▼
                       produits.db  [navigateur mobile]

Flux d’un scan

  1. Le sketch Arduino détecte une nouvelle carte MFRC522 et écrit son UID en majuscules sur le port série.
  2. Le thread lecture_rfid() du backend lit chaque ligne reçue.
  3. normaliser_uid() retire les espaces, tirets ou deux-points et uniformise la casse.
  4. ajouter_uid() bloque une relecture du même UID pendant deux secondes.
  5. SQLite cherche le produit. S’il existe, le scan alterne entre ajout et retrait de l’article.
  6. Le navigateur interroge /api/cart toutes les secondes, puis rafraîchit le panier et la notification.

Données et état

EmplacementContenuDurée de vie
produits.dbUID, nom, prix, catégorie, stockPersistante
cart_itemsArticles du panierMémoire du serveur
cart_totalSomme des prix des articlesMémoire du serveur
last_scanDernier UID et résultatMémoire du serveur
Conséquence : un redémarrage de backend.py vide le panier, mais conserve le catalogue SQLite.

Choix importants

  • Verrou cart_lock : protège le panier, consulté à la fois par le thread RFID et les requêtes HTTP.
  • Toggle au scan : le même UID retire l’article s’il est déjà présent ; c’est une simplification pratique pour la démonstration.
  • Poll côté interface : facile à comprendre et suffisant pour un prototype ; WebSocket serait préférable pour une version à grande échelle.
